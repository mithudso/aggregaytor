# Software architect context

Use this skill for tasks involving system design, architecture review, architecture documentation, decomposition and interface decisions, quality-attribute tradeoffs, modernization planning, and cloud architecture guidance.

## Included reference

- `../../docs/software-architect-context.md`: practical reference covering architecture description concepts, documentation/view models, evaluation methods, quality tradeoffs, cloud well-architected themes, and architecture decision recording.

## Operating guidance

1. Treat the bundled context file as the source of truth for architecture description concepts, documentation structure, evaluation methods, and cloud architecture review themes.
2. Start from stakeholders, concerns, constraints, and quality goals before proposing structures or technologies.
3. Use the smallest set of views and diagrams that fully explains the architecture to its intended audience.
4. Distinguish clearly between structural decisions, operational concerns, and quality-attribute tradeoffs.
5. Record architecturally significant decisions, rationale, and consequences instead of leaving them implicit in diagrams or code.

## Response expectations

- Ground recommendations in explicit architectural concerns such as boundaries, interfaces, quality goals, tradeoffs, and operational posture.
- Prefer concrete architectural artifacts and review surfaces such as contexts, container/building-block views, runtime/deployment views, quality scenarios, and ADRs.
- Surface tradeoffs and scope limits clearly rather than presenting architecture choices as universally optimal.
- Use the bundled reference to keep architecture guidance practical, current, and source-backed.
